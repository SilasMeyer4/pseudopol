# NOTES 03.06.2025

## Ideen zur Architektur Pseudopol

- Pseudopol sowohl als API als auch als GUI anwendung
- Projekt weiterhin mit nur einem Websocket
-> Messagetype soll plannmäßig als Trait implementiert werden. 
   + hilft in der API, dass user einfach neue Types hinzufügen können ohne enum erweitern zu müssen.
- sonstiges: Language konventions werden nach der geschriebenen Sprache gewällt, nicht über das ganze Projekt vereineitlicht.
- Pseudopol wird keinen server laufen haben (keine freundesliste, kein machmaking etc)
-> Host dient als server, host wird state updates an clients schicken, clients erfragen nicht den state
   + weniger message austausch!
